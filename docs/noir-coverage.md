# Noir failure sources and `total` coverage

| Area | Operation | Can fail when | Covered by total |
|---|---|---|---|
| Integers | `+`, `-`, `*` on u8, u16, u32, u64, u128 | The exact result does not fit the type (overflow, or a negative difference); the compiler range-checks the raw result | Yes: add_or, sub_or, mul_or, saturating_add, saturating_sub, saturating_mul, wrapping_add_or, wrapping_sub_or, wrapping_mul_or (Field-domain, N up to 128), widening_mul, pow_or, abs_diff |
| Integers | `/`, `%` on u8, u16, u32, u64, u128 | The divisor is zero | Yes: div_or, div_rem_or, mod_or, div_ceil_or, mul_div_or, mul_div_ceil_or |
| Integers | `+`, `-`, `*` on i8, i16, i32, i64 | The exact result lies outside the signed range, for example 127i8 + 1 or -128i8 * -1 | Yes: add_or, sub_or, mul_or, saturating_add, saturating_sub, saturating_mul |
| Integers | `/`, `%` on i8, i16, i32, i64 | The divisor is zero, or the dividend is MIN and the divisor is -1 (both `/` and `%`) | Yes: div_or, div_rem_or, mod_or, div_floor_or, div_euclid_or, rem_euclid_or, mul_div_or, mul_div_ceil_or |
| Integers | Unary `-` on i8, i16, i32, i64 | The operand is MIN | Yes: neg_or |
| Integers | `<<`, `>>` on every integer type (the shift amount has the operand's type) | The shift amount is at or above the bit width; bits shifted out the top are dropped silently, which is not a failure | Partly: TotalShift (shl_or, shl_exact_or, shr_or on u8, u16, u32, u64, u128); shl_or, shl_exact_or, shr_or, rotate_left_or, rotate_right_or on Fields up to 128 bits with a Field amount; no signed shifts |
| Field | `/` | The divisor is zero (the hinted inverse w must satisfy b * w == 1) | Yes: inverse_or, field_div_or |
| Field | `pow_32` | The exponent is 2^32 or more (its 32-bit decomposition cannot reconstruct it) | Partly: to_le_bits_or, pow_or; no entry computes a Field power from a flagged exponent |
| Field | `assert_max_bit_size::<N>` | The value is 2^N or more | Yes: fits_bits, clamp_bits_or, fits_u1, fits_u8, fits_u16, fits_u32, fits_u64, fits_u128, lt |
| Field | `to_le_bits::<N>`, `to_be_bits::<N>` with N below 254 | The value is 2^N or more, so the N bits cannot reconstruct it; the 254-bit forms are total | Yes: to_le_bits_or, to_be_bits_or (N up to 253), to_le_bits_total, to_be_bits_total |
| Field | `to_le_bytes::<N>`, `to_be_bytes::<N>` with N below 32 | The value is 256^N or more; the 32-byte forms are total | Yes: to_le_bytes_or, to_be_bytes_or, chunk_to_le_bytes_or, chunk_to_be_bytes_or, to_le_bytes_total, to_be_bytes_total, u16_to_be_bytes, u32_to_be_bytes, u64_to_be_bytes, u128_to_be_bytes and their little-endian forms |
| Field | `from_le_bytes_checked`, `from_be_bytes_checked` | The 32 bytes encode an integer at or above the field modulus (shorter arrays cannot fail) | Yes: from_le_bytes_or, from_be_bytes_or, canonical_le_bytes_flag, canonical_be_bytes_flag |
| Field | `bn254::assert_gt`, `bn254::assert_lt` | The ordering does not hold (`lt` and `gt` themselves are total) | Yes: lt, gt, lte, gte, cmp_bits |
| Entry point | Integer- and bool-typed `main` parameters, including inside arrays, structs and `str` | The input lies outside the type's range: an unconditional RANGE on the input witness that no predicate disables, and nargo's ABI rejects the value before solving | Yes: to_u8_or, to_u16_or, to_u32_or, to_u64_or, to_u128_or, to_i8_or, to_i16_or, to_i32_or, to_i64_or, bool_or, fits_bits |
| Assertions | `assert`, `assert_eq`, `panic` | The condition is false for the given inputs, or `panic` is reached; under a dynamic `if` the constraint is multiplied by the branch condition | Yes: Outcome, require, and_outcome, guard, mask_field, mask_array, Select |
| Option | `unwrap`, `expect` | The option is None | Yes: some_or |
| Arrays | `arr[i]` read or write with a witness index | The index is at or above the array length; under a dynamic `if` the index is gated | Yes: index_or, set_or, subarray_or, index_flags_or |
| Arrays | `sort_via(ordering)` | The ordering is not reflexive, for example `<`, and the array holds equal elements, so the sortedness check on the result fails; `sort` uses `<=` and cannot fail | Partly: sort_or sorts W-bit Field arrays (flagged range) in integer order; no custom ordering |
| Vectors (`[T]`) | `vector[i]`, `insert`, `remove` with a witness index; `pop_front`, `pop_back`, `reduce` on an empty vector; `as_array` | The index is at or above the length, the vector is empty, or the length differs from the requested array size | No |
| BoundedVec | `push`, `extend_from_array`, `extend_from_bounded_vec`, `set_len`, `from_parts` | The resulting length would exceed MaxLen; for `from_parts`, also a nonzero element past the length | Yes: push_or, extend_from_array_or, extend_from_bounded_vec_or, set_len_or, from_parts_or, from_prefix_or |
| BoundedVec | `extend_from_vector` | The resulting length would exceed MaxLen | No |
| BoundedVec | `get`, `set` | The index is at or above the current length | Yes: get_or, set_or |
| BoundedVec | `pop` | The vector is empty | Yes: pop_or |
| Embedded curve | `embedded_curve_add`, `EmbeddedCurvePoint` `+`, `-`, `double` | Either input is neither (0, 0) nor on the Grumpkin curve; the black box is skipped under a false predicate | Yes: add, sub, double, decode_or, decode_xy_or, is_well_formed |
| Embedded curve | `multi_scalar_mul`, `fixed_base_scalar_mul` | A point is off the curve, a scalar limb is 2^128 or more, or lo + 2^128 * hi is at or above the Grumpkin group order (`EmbeddedCurveScalar::from_field` is total). In bb 6.0.0 also, for witness bases, valid points and scalars in a known relation to the gadget's public offset generators (for example a base equal to one): the solver accepts them and the gadget's x-coordinate assertions have no proof. Constant generator bases with witness scalars (`fixed_base_scalar_mul`) take a lookup-table path without those assertions, whose incomplete additions meet only through a discrete-log relation between bb's table offsets and G; edge scalars (0, 1, q - 1, p - 1, 2^128 - 1, 2^252) prove | Yes: msm_or (validates, then blinds the bases so every input has a proof), mul_or, mul_limbs_or, scalar_limbs_or; no entry calls `fixed_base_scalar_mul` |
| Signatures | `ecdsa_secp256k1::verify_signature`, `ecdsa_secp256r1::verify_signature` | The solver returns false for malformed keys and signatures, but for some inputs its witness cannot be proven by the backend: r below p - n with R.x = r + n on both curves, on secp256r1 r = s or r + s = n, small-order off-curve keys on secp256k1, and on both curves on-curve keys for which bb's multiplication meets equal x-coordinates in an incomplete addition (keys solved for a collision, secp256r1 keys related to bb's offset generator, secp256k1 inputs with R a short multiple of G); a key holder can construct all of these. The module header of noir/total/src/ecdsa.nr lists the classes found; the wrappers exclude the first three and blind the key against the last | Yes: ecdsa_k1_verify, ecdsa_r1_verify, ecdsa_k1_verify_fields, ecdsa_r1_verify_fields, ecdsa_k1_sig_admissible, ecdsa_r1_sig_admissible |
| Recursion | `verify_proof_with_type` | The proof, verification key, public inputs or key hash do not verify under a true predicate; the solver never checks, and the backend then cannot prove | No |
| Unconstrained code | Brillig traps: `/` and `%` by zero, `+` `-` `*` overflow, shifts at or above the width, out-of-bounds indexing, pop from an empty vector, `assert` | The hint's inputs trigger one of them: witness generation aborts even though the circuit's constraints may be satisfiable; a call under a false predicate is skipped | No |
| noir-lang/schnorr (outside the stdlib) | `verify_signature` | Both scalars are nonzero and the key is off the curve, a scalar limb is 2^128 or more, or a scalar is at or above the Grumpkin group order (the MSM black box rejects them); in bb 6.0.0 also a valid key in a known relation to the MSM gadget's offset generators, such as the generator o_2 itself, with any nonzero scalars (no proof) | Yes: schnorr_verify (the same scheme over msm_or), schnorr_inputs_ok |
| noir-lang/sha256 (outside the stdlib) | `sha256_var` | message_size exceeds the array length N | Yes: hash::sha256_var_or (Field length, flagged) |
| noir-lang/sha256 (outside the stdlib) | `sha224_var` | message_size exceeds the array length N | No |
| noir-lang/sha256 (outside the stdlib) | `partial_sha256_var_interstitial`, `partial_sha256_var_end` | message_size is not a multiple of 64 or exceeds N; for `partial_sha256_var_end`, real_message_size is below message_size, or message_size plus the trailing partial block exceeds N | No |
| noir-lang/keccak256 (outside the stdlib) | `keccak256` | message_size exceeds the array length N | Yes: hash::keccak256_var_or (Field length, flagged) |
| Aztec protocol_types (outside the stdlib) | `merkle_tree::root_from_sibling_path` | The leaf index is 2^N or more for a path of length N (its `to_le_bits::<N>` cannot reconstruct it) | Yes: merkle::merkle_root_or, merkle::is_member, merkle::merkle_root_sep_or |
| noir-lang/bignum (outside the stdlib) | `from_be_bytes`, `from_le_bytes`, `to_be_bytes`, `to_le_bytes`, `validate_in_field`, `validate_in_range` | The value is at or above the modulus, a limb is 2^120 or more, or the top limb or most significant byte is wider than the modulus allows | No |
| noir-lang/bignum (outside the stdlib) | `udiv_mod`, `udiv`, `umod` | The divisor is zero (the remainder cannot be below it), or either operand is at or above the modulus | No |
| noir-lang/bignum (outside the stdlib) | `/` (modular division) | The divisor is zero modulo the modulus | No |
| noir-lang/bignum (outside the stdlib) | `assert_is_not_equal`, `assert_is_not_zero` | The operands are equal, or the value is zero, modulo the modulus | No |
| noir-lang/bignum (outside the stdlib) | `+`, `-`, `*`, `sqr`, `neg`, `evaluate_quadratic_expression` | An operand is not a canonical value below the modulus with 120-bit limbs (for example built with `from_limbs_unsafe` or `set_limb` and never validated): the hinted quotient, carry and borrow flags cannot pass the limb range checks | No |
